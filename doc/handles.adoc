[#document-handles]
== Handles

A document holds one value, and a program reaches the values inside it through handles:
`wd::value`, which reads and writes, and `wd::const_value`, which reads. `doc.root()`, `doc["key"]`,
`doc[3]` and every navigation from a handle return one. A handle names one place in one document,
and is cheap to copy: it holds the document's address and the ids of nodes, not a pointer into
the tree.

[#document-handles-navigation]
=== Navigation never fails

In JavaScript, `doc.user.nick` is `undefined` when `user` has no `nick`, and `doc.n.x.y` throws a
`TypeError` when `doc.n` is a number. A handle never fails: it names one of three things, and
reads `undefined` where nothing is there.

[cols="2,2,3",options="header"]
|===
| A handle names | Made by | Reads, and `set` does

| a node
| navigation to a value that exists
| the value; `set` replaces it

| a missing member or element of a container that exists
| `obj["absent"]`, or `arr[9]` past the end
| `undefined`; `set` creates the member, or the element, filling the elements between with `null`

| nothing
| navigation through `undefined`, a scalar, or an erased value
| `undefined`; `set` fails with `errc::type`, JavaScript's `TypeError`
|===

A handle resolves its place again at every call, so it reads what is there now: `user["nick"]`
reads `undefined` until a `set` creates the member, and the same handle then reads the new value.
A handle stays valid while the document grows and its image moves to a larger buffer; it reads
`undefined` once its value is erased; and it is invalid once its document is moved from or
destroyed, as a container's iterators are.

[#document-handles-reading]
=== Reading

`kind()` is JavaScript's `typeof`, with `null`, arrays, dates and bytes told apart: one of the
enumerators of `wd::kind`, `undefined`, `null`, `boolean`, `number`, `string`, `date`, `bytes`,
`array` and `object`, each with an `is_` function. `get<T>()` reads the value as `T` and returns
a `result`: `errc::type` for another kind, and `errc::range` for a number that `T` cannot hold
exactly. `T` is `bool`, any integer type, a Boost.Decimal type, the traits' number type,
`std::string`, `std::string_view`, `std::u16string`, `std::u16string_view`, `wd::date_ms`,
`std::vector<std::byte>` or `std::span<const std::byte>` (<<document-strings>>).

`value_or(fallback)` is JavaScript's `??`: the value `get<T>()` gives, `T` being the fallback's type, or
the fallback when nothing is there, when the value is `null`, or when it cannot be read as `T`.
`contains(key)` is `key in v` for an object, `size()` an object's key count or an array's length,
and `length()` an array's length or a string's in UTF-16 code units, as JavaScript counts them:

document's image: each is valid until the document's next change, which may move the image.

[#document-handles-writing]
=== Writing

`set(x)` is assignment. It takes `bool`, any integer type, the Boost.Decimal types, the traits'
number type, text (`std::string_view`, `const char*`, `std::string`, `std::u16string_view`), bytes
(`std::span<const std::byte>`), a `wd::date_ms`, `nullptr` or `wd::null`, the literals
`wd::object` and `wd::array`, which are JSON written in {cpp}, a handle or a document of the same
traits, which it copies, and `wd::undefined`. A character is not a number: `set('a')` does not
compile, nor does `set` of a `float`, nor of a `double` unless the traits' number type is one.

`erase(key)` is `delete`, and returns whether the key was there. `set(wd::undefined)` erases a
member too: JavaScript keeps a member whose value is `undefined`, and writes nothing for it, while a
document never stores `undefined`. In an array, it stores `null`, the text JavaScript writes for
it; at the root, the document holds `undefined`, and writes nothing. `assign_from(source)` is
`Object.assign`: each member of the source is set here, in its order, as one operation that
completes or changes nothing; an array's elements are its members `"0"` to `"n-1"`, and `null` or
`undefined` add nothing.

[#document-handles-copies]
=== Copies, never aliases

seen through the other. A document is a tree, as JSON is, so `set` of a handle copies the subtree:

[listing]
----

A copy reads its source before it changes anything, so a value may be copied into its own
subtree. Between documents, copies need the same traits, and any storage. `doc.clone()` copies a
whole document into a new owned one, as `structuredClone` would.

A `wd::value` is not a regular value: with exceptions, `x = y` writes where `x` points, and
never makes it point elsewhere (<<document-exceptions>>). It must not be swapped or sorted:
`std::swap(x, y)` assigns through both handles, leaving both places holding the value of `y`, and
`std::sort` over a range of handles writes the document's values the same way. Read the values
out, sort them, and set them back.

=== Iteration and equality

the order of the traits' object policy (<<document-order>>), and a `for` over an array's handle

A range reads the document as it is when each step is taken, so changing the container it walks
is undefined, as it is for a standard container.

`==` compares two values structurally, which JavaScript does not: the same kind; numbers by value,
so `1`, `1.0` and `1e0` are equal; strings, dates and bytes by value; arrays element by element;
objects with the same keys, each holding an equal value, in any order. Two documents compare
their roots.

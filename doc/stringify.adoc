[#document-stringify]
== Writing JSON

`wd::stringify(v, indent)` is `JSON.stringify(v, null, indent)`, and writes its exact bytes: the
keys in the policy's order (<<document-order>>), strings escaped as `JSON.stringify` escapes them
(<<document-strings>>), numbers as JavaScript writes them (<<document-numbers>>), a date as
`Date.prototype.toJSON` writes it, and bytes by the traits' policy. It is a function of a handle
or of a document, and a member of both, `doc.stringify(2)` and `doc["user"].stringify()`:

[source]
----
include::{examples}/document_quick_start.cpp[tag=stringify,indent=0]
----

The indent is JavaScript's: 0 writes compactly, a larger one is clamped to 10 spaces, and an empty
array or object is written `[]` or `{}` at any indent. A value that is `undefined`, a handle of
nothing or a document that holds `undefined`, writes no text, as `JSON.stringify(undefined)`
returns none. `stringify` returns a `std::string`, so its only failure is the standard library's
`std::bad_alloc`; a program that must not meet even that writes to a sink of its own.

[#document-stringify-to]
=== In pieces, to a sink

`wd::stringify_to(v, sink, indent, chunk)` writes the same bytes as `stringify`, in pieces of at
most `chunk` bytes, 4096 unless told otherwise, to a sink: any callable that takes a
`std::string_view` and returns `void` or `wd::result<void>`. A failure the sink returns stops the
writing and is returned; an exception it throws propagates. The document is unchanged either way,
and a writer holds no recursion, so a document nested as deep as memory allows is written:

[source]
----
include::{examples}/document_streaming.cpp[tag=stringify_to,indent=0]
----

[listing]
----
include::{examples}/document_streaming.expected[lines=12..13]
----

The first sink writes a bar after each piece of 8 bytes; the second keeps the first piece, then
fails, which stops the writing there.

= document: JSON as JavaScript has it, for {cpp}
:toc: left
:toclevels: 1
:idprefix:
:sectanchors:
:example-caption!:
:attribute-missing: warn

webcpp::document brings JavaScript programmers the wonders of {cpp} without the risks of {cpp}. It is
a header-only JSON document for {cpp}20, one of the libraries of
https://github.com/webcpporg/webcpp[webcpp], whose behaviour is JavaScript's: what `JSON.parse`,
property access, assignment, `delete`, the array methods and `JSON.stringify` do in JavaScript,
document does in {cpp}, with the same key order and the same text out, so that a JavaScript peer
and a {cpp} program agree byte for byte.

Its tree lives in one relocatable image, built through an allocator, so that a document can live in
a memory segment, be made durable, be shared between threads and processes, and travel as binary
and be opened where it lands, with no parse. It reads and writes JSON and NDJSON streams, keeps
numbers exact, seals images with a CRC, and answers queries over ordered keys, from {cpp} and from
JavaScript. Its core never throws: every operation that can fail returns its error as a value.

This page teaches document concept by concept, from JavaScript's side: what each part does, its
smallest example, its variations and its rules. Every {cpp} program it shows was compiled and run,
natively and, where the program does not need Boost.Asio, Boost.Cobalt, threads, shared memory or
xactor, on emscripten and for wasm32-wasip2 and wasm32-wasip3 too (<<document-testing>>), and printed
the output shown under it, which is what Node prints for the same JavaScript wherever the page does
not say otherwise. The listings of the JavaScript module are copied from the tests that run it. The
<<reference,reference>> that closes it lists every name the headers declare.

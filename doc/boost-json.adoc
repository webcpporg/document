[#document-vs-boost-json]
== Compared with Boost.JSON

Boost.JSON is the JSON library of Boost, and document reads JSON with its parser. Its document,
`boost::json::value`, is built for speed, and document is built to behave as JavaScript does and to
move as bytes: the two make different choices, and this section puts them side by side. Each part of
the program below runs the same JSON through both libraries and prints both outputs. The line of
document is what JavaScript gives where the part says nothing else, and the line of Boost.JSON is
what that library gives. It uses Boost.JSON by `<boost/json.hpp>`, beside document's header:

[#document-vs-boost-json-image]
=== An image copied and opened in place

A `boost::json::value` points into its memory resource, so its bytes cannot be copied to another
buffer: the only way to move it is to serialize it and parse it again. document's image is the
document, and a copy of its bytes in a buffer of the program's own, opened there, is the same
document with no parse (<<document-images>>):

[#document-vs-boost-json-speed]
=== What Boost.JSON does better

document is not a fast JSON tree. Boost.JSON parses faster, stringifies faster, finds a key faster
(it hashes, where document walks an ordered tree) and splices an array faster, and its values are
smaller than document's images: a node of an image takes 192 bytes whatever it holds
(<<document-parsing-memory>>). The benchmarks measure each of these against Boost.JSON and against
JavaScript (<<document-benchmarks>>, and <<document-benchmarks-reading>> for where document is slower
and why). The reasons to choose document are the ones above, and the ones that no parser has: an
image that is sent as it is, opened in place and shared between threads and processes, which
<<document-wire>> and <<document-sharing>> teach.
